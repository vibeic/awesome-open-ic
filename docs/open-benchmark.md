# Open Benchmark

Open, **agentic / LLM benchmarks for AI-driven IC design** — RTL generation, verification, and full-flow agent tasks. This is a different category from [Benchmarks](benchmarks.md), which lists traditional circuit / synthesis / place-and-route suites.

Where a benchmark has been **run with the [Vibe-IC](https://github.com/vibeic/vibe-ic) plugin + MCP-EDA** (each score names the plugin version that produced it, and the Claude model where the run artifact records one; latest runs: v1.4.81), the highest blind pass@1 is annotated in parentheses after the entry — same style as the `(🟢 MCP-wrapped)` tags elsewhere in this list. All scores are fully blind (prompt-only, no test access) and graded by each benchmark's **official upstream testbench**. Run artifacts (`pass_at_1.json` + a per-run `RESULT.md`) live in **[vibeic/vibe-ic → benchmark-data/evaluation/](https://github.com/vibeic/vibe-ic/tree/main/benchmark-data/evaluation)**. Entries without a score have not yet been run with Vibe-IC.

> **Per-problem stability — the 5-tier classification.** Beyond the headline pass@1, every problem is classified on the **[ATLAS](https://github.com/reyerchu/ATLAS) 5-tier ladder** that measures how far up the program-first "Ratchet" each case has been pushed: **T1** = deterministic program emit (no AI, passes the golden) · **T2/T3** = AI authors under a program-extracted spec + a conformance gate · **T4** = not yet gate-able · **T5** = a *proven* golden/oracle defect (never "the AI can't"). A score that rises because more cases reach T1/T2 is real, compounding progress; a T5 floor is only valid after the original golden is shown to fail its own testbench. See the `golden-benchmark` skill in ATLAS.

- **[VerilogEval-v2 (spec-to-RTL)](https://github.com/NVlabs/verilog-eval)** — NVIDIA's VerilogEval v2 spec-to-RTL task (156 problems): structured-interface prompt → full module, iverilog-scored. The frontier reference (~90%) for spec-driven RTL generation.
  `License: see repo (NVIDIA)` | `Last commit: 2024` | *(🔵 **Vibe-IC + MCP-EDA (v1.4.81): 98.08%** — 153/156 **single-shot** (no close-loop round), **at the defect floor = 100% of solvable**: the 3 misses are upstream dataset defects — a suspected-defective golden, a spec-ambiguous K-map mux mapping, and an irreducible golden that fails its own TB. Earlier: 152/156 on v1.4.68 and v1.4.74; 153/156 on Claude Fable 5 v1.3.88.)*
- **[VerilogEval-Human](https://github.com/NVlabs/verilog-eval)** — NVIDIA's VerilogEval code-completion track with concise human-written descriptions (156 problems, iccad2023). The standard module-scale "write correct Verilog from a human prompt" benchmark.
  `License: see repo (NVIDIA)` | `Last commit: 2024` | *(🔵 **Vibe-IC + MCP-EDA (v1.4.81): 98.72%** — 154/156 **single-shot** (no close-loop round), **at the defect floor**: both misses are upstream dataset defects — a suspected-defective golden and a spec-ambiguous K-map mux mapping. Identical score and identical fail set on v1.4.68, v1.4.74 and v1.4.81. Earlier: 153/156 on Claude Fable 5 v1.3.88.)*
- **[RTLLM](https://github.com/hkust-zhiyao/RTLLM)** — Open natural-language → RTL benchmark (~50 designs: arithmetic / memory / control / misc) with reference RTL, testbenches, and self-planning prompt baselines. Module-scale.
  `License: MIT` | `Last commit: 2024` | *(🔵 **Vibe-IC + MCP-EDA + Claude Fable 5 (v1.3.88): 98.0%** — 49/50 via the runner-driven flow (Shape B, `--skip-phase3`), blind, graded by RTLLM's own `testbench.v`; single-shot 47/50 = 94.0%, converged after ONE blind close-loop round. **100% (49/49) excluding the single irreducible dataset defect** (`ring_counter` — golden fails its own TB); rigorous 97.92% (47/48) excluding 2 non-discriminating upstream TBs. Previous residuals `radix2_div` / `freq_divbyeven` / `asyn_fifo` now PASS (forked iverilog-14 toolchain + captured plugin fixes). Earlier Opus-4.8 v1.2.7 campaign: 46/50 = 92.0%.)*
- **[PyHDL-Eval](https://github.com/cornell-brg/pyhdl-eval)** — Spec-to-RTL LLM evaluation across Verilog **and Python-embedded HDLs** (PyMTL3, PyRTL, MyHDL, Migen, Amaranth); 168 problems with reference solutions and testbenches.
  `License: MIT` | `Last commit: 2024`
- **[RTL-Repo](https://github.com/AUCOHL/RTL-Repo)** — Benchmark for LLMs on **large-scale, multi-file** RTL projects (real GitHub Verilog repos) rather than single-module problems.
  `License: Apache-2.0` | `Last commit: 2024`
- **[CVDP — Comprehensive Verilog Design Problems](https://github.com/NVlabs/cvdp_benchmark)** — NVIDIA's 1,500+ task / 13-category benchmark (RTL gen, testbench, assertion, bug-fix, code-completion) in agentic and non-agentic modes, simulation-scored. The current open bar for agentic, multi-file chip-design tasks.
  `License: see repo (NVIDIA)` | `Last commit: 2025` | *(🔵 Vibe-IC + MCP-EDA (v1.2.63): **243/302 = 80.46%** official-compliant blind pass@1 on the public **`nonagentic_code_generation_no_commercial`** set (302 problems), scored by the upstream `run_benchmark.py` in the pinned `cvdp-sim` image. **Prompt+context-only compliance** — per the CVDP paper (arXiv:2506.14074 §2) + `README_NON_AGENTIC`, the model sees ONLY `input.prompt` + `input.context`; the hidden test harness (`.env` TOPLEVEL, cocotb testbench) and the golden `output.*` are OFF-LIMITS oracle. This is a structural invariant of the plugin, enforced by a regression guard that proves the emitted RTL is byte-identical with vs without the harness+golden present across all 302 records. The full 1,500-task commercial set remains gated by NVIDIA/Turing; the golden solutions are stripped from the public set (anti-contamination), so the residual is the genuine prose-vs-oracle floor. Run artifacts: [benchmark-data/evaluation/cvdp/](https://github.com/vibeic/vibe-ic/tree/main/benchmark-data/evaluation/cvdp).)*
- **[MetRex](https://github.com/scale-lab/MetRex)** — Benchmark for LLM **reasoning about post-synthesis metrics** (area / delay / power) of Verilog designs; 25,868 designs with their synthesized metrics (ASP-DAC'25).
  `License: see repo` | `Last commit: 2025` | *(🔵 Vibe-IC **dissolves the prediction premise**: rather than asking an LLM to *predict* metrics, it runs the **exact MetRex yosys + sky130 recipe** and reproduces MetRex's own golden — **area median 1.15 % abs-diff, 90 % within 5 %** over a deterministic 50-design sample (cell-count exact on 19/19 tiny designs). A real-synthesis demo, **not a pass@1** — MetRex grades metric-reasoning, not generation.)*
- **[ResBench](https://github.com/jultrishyyy/ResBench)** — **Resource-aware** benchmark for LLM-generated FPGA designs — scores LUT / FF / DSP utilization alongside functional correctness.
  `License: see repo` | `Last commit: 2025`
- **[ChipAgentsBench](https://www.ieee-edps.com/archives/2025/c/1000zhang.pdf)** — ChipAgents' agentic design + verification benchmark (IEEE-EDPS 2025): ~30k-line / ~112-file real projects with UVM-generation and waveform-debugging task types; SOTA open-source agents score <25%. A task subset + test harness + leaderboard were announced.
  `License: subset release announced (paper)` | `Last commit: 2025` | *(planned — Vibe-IC run once the open subset ships)*
